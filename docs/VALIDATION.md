# Validation on a public dataset

**Dataset:** OpenSSH_2k.log from LogHub 2.0 (https://github.com/logpai/loghub-2.0, `2k_dataset/OpenSSH/`), a public sample of real SSH server logs. Stored here as `docs/OpenSSH_2k.log`.

**This dataset has no attack labels, so precision and recall cannot be computed and none are claimed.** What follows is a descriptive run plus a sanity check against raw counts.

| Measure | Result |
|---|---|
| Lines in file | 2,000 |
| Lines turned into sign-in events | 630 (629 failed, 1 successful). The rest are pre-authentication chatter that is not a sign-in outcome. |
| Alerts raised | 13 (7 brute force, 5 password spray, 1 distributed attack) |
| Addresses that raised alerts | 6 |
| Incidents (alert score >= 50) | 4, all Credential Access, one address each |

**Sanity check (not ground truth).** Counting raw "Failed password" / "Invalid user" lines per address independently: 24 addresses had at least one such line, and 7 had 8 or more. Hindsight raised alerts for 6 of those 7 (the flagged addresses had 24 to 295 such lines). The 7th (52.80.34.196) was not alerted, most likely because its failures were spread out below the burst thresholds. Note that one failed attempt can appear as two lines ("Invalid user" and "Failed password for invalid user"), so raw counts overstate the number of real attempts.

**What this does and does not show.** It shows the parser handles real syslog data and that the burst rules fire on obvious brute-forcing without crashing or producing a flood of noise. It does not show detection accuracy on a labelled intrusion dataset. A proper evaluation needs one (for example CICIDS2017 or LANL) and was not done.

**Our synthetic demo** (`logs/sample_logs.csv`, generated by `app/generator.py`) scores precision 1.0 and recall 1.0, but it was written alongside the detector, so that score only proves the pipeline works end to end.

Reproduce: `python -m app.cli docs/OpenSSH_2k.log --format json -o out.json`
